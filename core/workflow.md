# 工作流

四个模块共用一套三步法。目的是别在还没确定值不值得查之前，就把算力花光。

```
Step 1  预判
         快速扫 3-5 个入口，建立全局认知
         → 输出预判报告：目标是什么、有哪些面、建议深入哪个方向
              ↓
Step 2  确认方向
         由人选定关注点；这一步不跳过，也不替人决定
              ↓
Step 3  深入
         按 core/routing.md 选工具，展开分析
         → 输出完整报告，每条结论按 docs/evidence.md 写三件套
```

## 各步的产出要求

**预判**：只做低成本观测。列清楚看到了什么、没看到什么、哪些是推断。不要在这一步给评级。

**确认**：写进案例的"范围"一栏。范围变了要重新走预判，不要边查边扩。

**深入**：所有命中先过 `docs/verification.md`；所有结论标注 observation / inference / unknown；最后附一节"局限与未验证项"。

## 什么时候可以省掉步骤

单个明确对象（比如一个已知函数、一条固定路径）可以只跑 Step 3，但案例里要写明"对象已确定，跳过预判"。除此之外不省。

## 和证据规范的关系

工作流管**顺序**，证据规范管**质量**。顺序对了但证据不合格，结果依然停在候选。
