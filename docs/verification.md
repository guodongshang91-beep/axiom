# 命中不等于结论

> 这是本仓库最要紧的一篇。工具换掉无所谓，这套判定逻辑不能丢。

在防护成熟的目标上，未经校准的扫描命中，假阳性率可以到 100%。同一套脚本、同一批目标，原始"中高危"若干条，校准后为 0；换一条链路（子域 + 前端 bundle）并带上对照后，才拿到真实结果。差别不在扫描量，在判定方式。

## 五道防线

| # | 防线 | 做法 |
| --- | --- | --- |
| 1 | 随机路径基线 | 请求一个不可能存在的随机路径，与候选路径比状态码、长度、正文 md5；全站 catch-all 时所有 200 都作废 |
| 2 | 收紧特征 | 只用组件独有词做正则，不用 HTML 通用词（"登录""管理"这类必然误报） |
| 3 | 同指纹去重 | 同一 md5 / 同一响应体只算一次，别把 232 个路径当成 232 个问题 |
| 4 | 拦截页识别 | WAF / 统一错误页按关键词识别，命中即标 `WAF_BLOCK`，不计入结果 |
| 5 | 回显识别 | 请求里的字符串被原样回显时标 `ERR_ECHO`，属于反射而非执行 |

实现时统一 `allow_redirects=False`：跟踪跳转会把基线对比搅乱。参考实现在 `targets/web/tools/unauth_scan.py` 和 `toolkit/verify_hit.py`。

## 进报告前的四件事

1. 原始响应存盘（头 + 体），不只是状态码。
2. 与随机路径基线对照，差异显著才算候选。
3. 换时间、换来源至少重现两次。
4. 写清局限：影响范围、需要的前置条件、没能验证的部分。

任何一步缺了，结果停在"候选"，不写进案例。

## 三个具体场景

- **软 404**：`/admin`、`/h2-console`、`/.env` 全部 200 且长度一致，通常是同一个 SPA 首页。双基线（随机路径 + 首页）比对，只信显著差异。
- **JSONP / 回调注入**：`1?x=y:0` 这类三元式可以绕过对 `&&`、`=` 的过滤；还缺 `nosniff` 才成立。响应里出现字符串不等于脚本执行，用无头浏览器的控制台输出或 `document.title` 侧信道证。
- **改动是否生效**：注入 / 补丁 / 配置改完了不算完，要在链路上验证（读实际请求、读实际返回、读进程状态）。"文件写对了"和"效果发生了"是两件事，`toolkit/verify_armor.py` 是这个思路的一个实例。

## 一句话

**未验证 = 不存在。** 扫描器负责给候选，人负责给结论。
