# product · 产品与技术栈拆解

来自 **逆向工程 Agent**：基于公开可观测信息，看透一个产品怎么做的、为什么这么做、是不是真的在做。这一层不碰二进制，输出的是结构化拆解报告。

## 目标类型

网站 / Web 应用 / 移动 App / 小程序 / SaaS / AI Agent / 开源项目 / API 服务 / 浏览器插件 / 桌面应用。仅限公开可观测信息。

## 方法

**四层拆解**（前端竞品分析）

| 层 | 看什么 |
| --- | --- |
| 信息架构 | 导航结构、页面层级、内容组织 |
| 功能模块 | 核心功能、辅助功能、隐藏功能、付费墙 |
| 交互设计 | 用户流程、操作路径、反馈机制 |
| 技术栈识别 | 框架、UI 组件库、构建工具、CDN、字体、统计 |

**后端逻辑推演**：接口暴露面 → 服务边界 → 数据模型推断 → 业务流程。刻意标成推断，不冒充观测。

**五维验证**：前端成熟度、API 完整度、团队公开活跃度、AI 深度（是否真 AI）、宣称与实际的一致性。每维 🟢 / 🟡 / 🔴 评级，评级跟着证据走。

**协议与架构**：REST / GraphQL / gRPC / MCP 等通信方式、编排层、工作流状态机。

## 工作流

预判（扫 3–5 个入口）→ 人确认方向 → 深入。完整规则见 `core/workflow.md`。不浪费算力，也不替人决定关注点。

## 证据形态

公开页面与接口行为、依赖与版本线索、响应时间与错误形态、第三方引用。每条结论按 `docs/evidence.md` 分 **事实 / 推断 / 置信度** 三栏写，防幻觉的关键是把推断单独列出来，而不是把报告磨得看起来很确定。

## 已知局限

- 基于外部观测，看不到内部实现；"用了什么数据库"这类结论天然只能是推断。
- 公开信息会变，报告要带采集时间。
- 评级用于横向比较，不是安全结论，也不是采购建议。
