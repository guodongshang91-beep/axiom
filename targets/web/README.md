# web · 黑盒侦察与判定

并入 `ReverseKit` 的 web-recon / src-hunt 脚本，按 `docs/verification.md` 的判定逻辑重排。核心不是"扫到什么"，是"怎么证明不是假的"。

## 目标类型

站点、接口、前端 bundle、子域资产。只处理可公开观测的对象，不放真实目标清单。

## 首选工具

| 脚本 | 作用 |
| --- | --- |
| `tools/probe.py` | 原始 HTTP 请求，保留完整响应 |
| `tools/dnsx.py` | DNS 记录收集 |
| `tools/headers_check.py` | 方法、响应头、CORS 检查 |
| `tools/jsonp_fuzz.py` | 回调字符与 WAF 指纹探测 |
| `tools/unauth_scan.py` | 路径探测 + 五道假阳性防线 |

所有脚本的目标走参数，不写死域名；示例一律用占位符。

## 证据形态

原始请求与响应（头 + 体）、状态码、响应体 md5、与随机路径基线的差异、bundle 里抽出的地址线索。

## 判定要点

- **软 404**：随机路径基线与首页双对照，只信显著差异；全站 catch-all 时所有 200 作废。
- **JSONP**：`1?x=y:0` 这类三元式能绕开对 `&&`、`=` 的过滤，但缺 `nosniff` 才成立；响应里出现字符串不等于脚本执行，用无头浏览器控制台或 `document.title` 侧信道证。
- **bundle 线索**：抽出的 OSS 地址、非标端口、内部地址只是候选，归属要靠"自有 JS 引用该地址"这样的证据绑定；只取文件头，隐私信息打码。
- **任何 200** 都要和随机路径对照。命中先进候选，过完 `docs/verification.md` 的四件事才进报告。

## 已知局限

- 扫描结果只能反映探测时刻、探测来源看到的状态。
- WAF 与风控会随来源变化，结论必须带时间与来源。
- 仓库不提供目标清单，也不提供针对具体站点的利用代码。
